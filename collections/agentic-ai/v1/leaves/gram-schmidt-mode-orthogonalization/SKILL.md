# gram-schmidt-mode-orthogonalization

## Summary

Orthogonalizes the (3,3) and (4,4) harmonic SNR time series against the (2,2) mode via Gram–Schmidt within the IAS-HM mode-by-mode filtering pipeline, so cross inner products between harmonic modes vanish before trigger ranking.

## When to use

Use when combining matched-filter SNR time series from multiple harmonics ((2,2), (3,3), (4,4)) whose templates are not exactly orthogonal, e.g. when building the h⊥ relation (Eq. 11) for mode-by-mode GW searches.

## When NOT to use

- When running a quadrupole-only search with a single (2,2) template — there are no cross-mode inner products to orthogonalize
- When the input is already an orthogonalized SNR set (pairwise cross inner products already vanish) — re-orthogonalizing is redundant

## Inputs

- Complex SNR time series for (2,2), (3,3) and (4,4) modes per template, obtained by mode-by-mode matched filtering of pre-processed GW strain data
- Noise-weighted inner-product matrix among the three mode SNR time series (and its Cholesky factor)
- Template bank entries with harmonic waveform modes generated by lalsimulation

## Outputs

- Orthogonalized, normalized (2,2), (3,3) and (4,4) SNR time series for all templates with vanishing pairwise cross inner products
- orthogonalized_snr.npz file storing the orthogonalized SNR time series (numpy format)

## How to apply

Generate the (2,2), (3,3) and (4,4) harmonic waveform modes for each template bank entry with lalsimulation and matched-filter the pre-processed GW strain data with each mode separately to obtain complex SNR time series. Compute the noise-weighted inner-product matrix among the three mode SNR time series and take its Cholesky factor, corresponding to the h⊥ relation of Eq. 11. Apply Gram–Schmidt keeping (2,2) fixed: orthogonalize (3,3) against (2,2), then (4,4) against (2,2) and the already-orthogonalized (3,3), normalizing each series so all cross inner products vanish. Save the orthogonalized SNR time series for all templates to orthogonalized_snr.npz with numpy. The rationale is that raw harmonic templates are not exactly orthogonal, so mode-by-mode filtering must decorrelate the mode SNRs before the pipeline's trigger-ranking statistics can optimally combine them while triggering only on physically allowed combinations.

## Examples

```
import numpy as np; snr = np.load('orthogonalized_snr.npz'); ip = np.vdot(snr['22'], snr['33']); assert abs(ip) < 1e-8
```

## Evaluation signals

- Pairwise cross inner products between the orthogonalized (2,2), (3,3) and (4,4) SNR time series vanish to numerical precision for a sample of templates
- The orthogonalized series are normalized (unit noise-weighted norm) after Gram–Schmidt
- The orthogonalized_snr.npz file contains SNR time series for all templates in the bank
- The ordering is preserved: (2,2) fixed, (3,3) orthogonalized against (2,2), then (4,4) against both (2,2) and orthogonalized (3,3)

## Limitations

- The three modes (22, 33, 44) are hard-coded in a few places in the current gwIAS-HM code; generalization to an arbitrary number of ell=m modes is planned but not yet implemented
- Only Hanford and Livingston detectors are hardcoded in the current pipeline version
- The orthogonalization assumes the noise-weighted inner-product structure; changes to the noise model require recomputing the inner-product matrix and its Cholesky factor
