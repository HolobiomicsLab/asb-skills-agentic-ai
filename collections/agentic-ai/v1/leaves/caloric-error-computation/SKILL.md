# caloric-error-computation

## Summary

Compute the percentage error between the summed calories of LLM-generated meal plans and user-defined caloric targets, verified against USDA FoodData Central reference values, to quantify how accurately each model adheres to dietary targets.

## When to use

Use when evaluating LLM-generated meal plans against user-defined caloric targets and USDA reference values, e.g. reproducing the NutriGen per-input error matrix across multiple models.

## When NOT to use

- The analysis goal is processing speed or computational efficiency of models rather than nutritional accuracy (use the processing-time comparison instead).
- Meal plans were generated by a non-NutriGen framework without user-defined caloric targets, so no target exists to compute percentage error against.
- Input is qualitative dietary-adherence assessment rather than per-item caloric sums compared to a numeric target.

## Inputs

- LLM-generated meal plans (3 replicates per model per 10 user inputs) from the NutriGen Jupyter Notebook
- User-defined caloric target values for each of the 10 simulated user inputs
- USDA FoodData Central reference calorie values for meal items appearing in the plans

## Outputs

- table1_error_matrix.csv: 10x10 (models x inputs) percentage-error matrix with '-' placeholders for failed generations
- Average per-input percentage error against the caloric target for each model

## How to apply

For each of 10 simulated user inputs, prompt each LLM (e.g. GPT-3.5 Turbo, Llama 3.1 8B, DeepSeek V3) three times through the NutriGen framework to generate a personalized meal plan. Sum the per-item reported calories for every plan with pandas, then retrieve USDA FoodData Central reference values for the meal items appearing in the plans. Compute the percentage error of each summed plan against the user-defined caloric target for its input and average over the three replicates for every model-input pair. Assemble the results as a 10x10 error matrix (models x inputs), inserting '-' wherever a model failed to generate a plan. Validate by confirming the matrix is 10x10 with '-' placeholders and that the best-performing models reproduce the reported lowest percentage errors of 1.55% (Llama 3.1 8B) and 3.68% (GPT-3.5 Turbo).

## Related tools

- **NutriGen** (Framework used to generate the personalized meal plans whose caloric content is evaluated) — https://github.com/SamanKhamesian/NutriGen

## Evaluation signals

- The error matrix is 10x10 (models x inputs) with '-' placeholders wherever a model failed to generate a plan.
- The best-performing models reproduce the reported lowest percentage errors of 1.55% and 3.68%.
- Each cell averages three replicates per model-input pair rather than a single generation.
- Percentage errors are computed against the user-defined caloric target for each specific input, not a global mean.

## Limitations

- DeepSeek V3 struggled with accuracy, exhibiting a higher MAE of 10.45%, and was significantly slower in processing time than GPT-3.5 Turbo and Llama 3.1 8B.
- Some models failed to generate a plan for certain inputs, requiring '-' placeholders in the error matrix.
- Errors depend on the USDA nutrition database as the reliable reference; accuracy claims assume per-item reported calories are validated against USDA values.
