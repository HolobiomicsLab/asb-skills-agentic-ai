# frozen-encoder-feature-extraction

## Summary

Extracts visual tokens and text embeddings from a frozen Long-CLIP encoder (context length extended to 248 tokens) for Hateful Memes examples, supplying the prototype- and context-guided decoders of EVL-MCoT with fixed vision-language representations before fusion.

## When to use

Use when meme examples M = {I, T} need frozen visual token grids H in R^{N x M x D} and Long-CLIP text embeddings for hateful/benign CoT texts, prior to prototype-guided fusion or alignment scoring.

## When NOT to use

- Standard CLIP must be used instead of Long-CLIP when inputs exceed 20 tokens — the article notes 'The standard CLIP model struggles with inputs exceeding 20 tokens, while our CoT approach requires processing 150-word sequences', so standard CLIP encoders are the wrong choice for long CoT text.
- If the goal is fine-tuning the vision-language encoder itself rather than extracting fixed features for a downstream fusion module, this frozen-encoder setup does not apply.

## Inputs

- Hateful Memes multimodal examples M = {I, T} (meme image + caption text)
- Hateful and benign Multi-CoT text chains (n=3, m=3) generated by an MLLM (LLaVA-1.5-7B or GPT-4)
- Frozen Long-CLIP visual encoder weights
- Frozen Long-CLIP text encoder weights

## Outputs

- Visual token tensor H in R^{N x M x D} per meme image
- Text embeddings T_emb for hateful CoT texts and benign CoT texts per meme

## How to apply

Load each Hateful Memes example and encode the image with the frozen Long-CLIP visual encoder to obtain visual tokens H in R^{N x M x D}; do not update encoder weights during training. Encode both the hateful text and benign text generated as Multi-CoT chains (n=3, m=3 from an MLLM such as LLaVA-1.5-7B or GPT-4) using the frozen Long-CLIP text encoder, since standard CLIP struggles with inputs exceeding 20 tokens while the CoT approach requires ~150-word sequences. Keep all extracted tensors fixed so that training only affects the downstream prototype-guided token fusion, attention-based feature fusion, and context-guided attention layers (Eq. 2-7). Optimize only the fusion module with AdamW (lr 5e-5, weight decay 0.01, cosine scheduler, batch size 8 with gradient accumulation every 2 steps).

## Related tools

- **Long-CLIP** (Frozen visual and text encoder used to extract visual tokens H (R^{N x M x D}) and embeddings for hateful/benign CoT texts; extends context length to 248 tokens for long CoT sequences)
- **AdamW** (Optimizer (lr 5e-5, weight decay 0.01, cosine scheduler) for training only the fusion module downstream of the frozen encoders)
- **LLaVA-1.5-7B** (MLLM that generates the Multi-CoT (n=3, m=3) hateful and benign text chains that are subsequently encoded by the frozen Long-CLIP text encoder)

## Evaluation signals

- Visual tokens must have shape H in R^{N x M x D} and text embeddings dimension D matching the Long-CLIP hidden size for cross-attention (Eq. 2) to run without reshaping.
- Encoder weights must remain unchanged after training (frozen check); only fusion-module parameters (prototypes Pr, W_a, W_b, W_c, W_v, tau) should differ from initialization.
- Downstream reproduction: the module should reach ~75.88% accuracy and ~79.25 AUROC on Hateful Memes Test Seen (75.57/79.40 on Test Unseen).
- Ablation expectation: removing the Long-CLIP encoder in favor of a shorter-context encoder significantly reduces ACC and AUROC.
- Encoded CoT texts of ~150 words must be fully processed, confirming 248-token context handling without truncation.

## Limitations

- Removing Long-CLIP significantly reduces ACC and AUROC on Hateful Memes and MultiOFF, so the skill is dependent on the long-context encoder.
- The official repository (BGWH123/EVL-MCoT) currently provides only the core training code in train/; model definitions, configs, scripts, and pretrained weights are listed as upcoming.
- Reasoning chains can be long; the paper's future work targets shortening reasoning chains while maintaining performance.
