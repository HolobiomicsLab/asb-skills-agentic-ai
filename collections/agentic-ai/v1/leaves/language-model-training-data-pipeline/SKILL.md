# language-model-training-data-pipeline

## Summary

Pipeline for turning KSPDG spacecraft-control trajectories (navball-bot collected observation/action files) into tokenized textual training data and fine-tuning LLaMA models with parameter-efficient LoRA/DoRA settings, with runs tracked in Weights & Biases and artifacts published to Hugging Face.

## When to use

Use when raw agent or bot trajectory logs from the KSPDG environment (10/25/50-file variants) must be converted into LLM fine-tuning datasets and a LLaMA-3-8B agent must be trained via PEFT rather than prompted.

## When NOT to use

- The goal is evaluation of an already-trained agent inside KSPDG — the README states KSPDG 'provides evaluations environments, _NOT_ training environments for reinforcement learning algorithms'
- The strategy is prompt engineering or few-shot prompting with GPT-3.5 via the OpenAI API (LRM adjustments) rather than fine-tuning open LLaMA weights locally
- Training data was collected from human gameplay only (which the authors found degraded validation loss, 4.4e-1) rather than navball-bot trajectories

## Inputs

- Navball-bot collected KSPDG trajectory files (10/25/50-file dataset variants)
- KSPDG mission observation/state records serialized as textual prompts
- Hugging Face LLaMA-3-8B base model identifier
- llama3_finetune_config.yaml hyperparameter specification (Table 1 values)

## Outputs

- Tokenized fine-tuning datasets paired with target action token sequences
- LoRA/DoRA fine-tuned LLaMA-3-8B spacecraft-control checkpoints
- llama3_finetune_config.yaml capturing all training hyperparameters
- Weights & Biases run logs with training/validation loss curves
- Hugging Face model and dataset repositories (e.g. LLaMA 10 files sliding window, LLaMA 35 files quantized, LLaMA 50 files)

## How to apply

Collect trajectory files generated by the navball bot in the KSPDG (Kerbal Space Program Differential Games) environment, in the 10-file, 25-file, and 50-file dataset variants used by the authors. Transform real-time mission observations into textual user prompts (tokenization considerations handled with tiktoken-style BPE token counting), pairing each observation with the corresponding action token sequence. Fine-tune LLaMA-3-8B using LoRA (r=16, alpha=8, dropout=0.05) with DoRA enabled, Flash Attention 2, only the last 2 layers trainable, AdamW at learning rate 1e-4 with a cosine scheduler, 3 epochs, batch size 2 and gradient accumulation 2, and no quantization. Track every run in Weights & Biases, serialize the configuration to llama3_finetune_config.yaml, and publish resulting model checkpoints and datasets to Hugging Face repositories (e.g. the 10/35/50-file LLaMA variants). Compare the fine-tuned agent's pursuit-evasion score against the navball bot baseline (e.g. fine-tune-50-files scoring 11.86 vs Navball bot 34.34 on the authors' metric, where lower is better).

## Evaluation signals

- llama3_finetune_config.yaml parses successfully and every field matches Table 1: AdamW, lr 1e-4, cosine scheduler, LoRA r=16/alpha=8/dropout=0.05, DoRA enabled, Flash Attention 2, 3 epochs, last-2-layers trainable, batch size 2, gradient accumulation 2, no quantization
- Dataset file counts match the 10/25/50 navball-bot variants and each sample pairs an observation prompt with an action target
- Training and validation losses are logged in Weights & Biases (e.g. GPT LRM 0.2 run reached train 2.3e-2 / val 2.8e-2 as a reference regime)
- Fine-tuned agent's evaluation score on the KSPDG pursuit-evasion scenario is reported relative to the Navball bot baseline (34.34) and Lambert-MPC baseline (>18.24)
- Each fine-tuned checkpoint and its dataset variant are resolvable in the corresponding public Hugging Face repository

## Limitations

- Outcomes are 'highly hardware-dependent'; the article does not specify hardware used for local LLaMA training/inference
- Fine-tuning on human gameplay data caused validation loss to worsen to 4.4e-1 despite near-zero training loss (1.3e-4), indicating overfitting risk
- KSPDG runs non-blocking (game time does not pause while agents decide), so slow inference policies are inherently penalized at evaluation time
