# benchmark-reliability-table-reproduction

## Summary

Reproduces the inter- and intra-annotator reliability table (Table IX) of the LLMPathy empathy-labels study by computing Krippendorff's Alpha (ordinal) and mean absolute error for Llama-vs-Llama, GPT-vs-Llama, LLM-vs-crowd, and GPT-vs-crowd label pairs on NewsEmp24.

## When to use

Use when you have multiple annotation sources (e.g., LLM-generated empathy labels from repeated API calls, different LLMs, and crowdsourced gold labels) joined on shared instance IDs and need to quantify annotation consistency.

## When NOT to use

- The goal is model predictive performance (PCC/CCC/RMSE of Tables V and VIII), not annotation reliability — train/evaluate a RoBERTa or DeBERTa PLM instead
- Only a single annotation source exists for each instance, so no pairwise agreement can be computed
- Labels are nominal/categorical rather than ordinal; Krippendorff's Alpha at the ordinal level of measurement would be inappropriate

## Inputs

- LLM-generated label files from LLMPathy data/llm-generated-labels directory, keyed by original dataset IDs (message/article/speaker IDs)
- Crowdsourced NewsEmp24 training labels from the CodeLab competition 18810 deposit
- Python environment with pandas, numpy, and the krippendorff package (pip install -r requirements.txt)

## Outputs

- label_agreement_metrics.csv with Krippendorff's Alpha and MAE for each of the four annotator pairs
- Reliability pattern matching Table IX: alphas of 0.99, 0.80, 0.27, 0.19 within rounding tolerance

## How to apply

Load the LLM-generated label files from data/llm-generated-labels of the LLMPathy repository with pandas; each file carries the original dataset identifiers (message/article/speaker IDs). Load the crowdsourced NewsEmp24 training labels from the CodeLab competition deposit and join on those instance IDs. Compute Krippendorff's Alpha at the ordinal level of measurement with the krippendorff Python package for four pairs: Llama-vs-Llama (intra-LLM), GPT-vs-Llama (inter-LLM), Llama-vs-crowd, and GPT-vs-crowd. Compute MAE for the same four pairs with numpy, assemble the eight values into a table, and write label_agreement_metrics.csv. The reproduction check is the Table IX pattern: alpha ≈ 0.99 (Llama intra), ≈ 0.80 (inter-LLM), ≈ 0.27 and ≈ 0.19 (LLM-vs-crowd), within rounding tolerance.

## Examples

```
import krippendorff, pandas as pd; merged = pd.merge(llm, crowd, on='instance_id'); a = krippendorff.alpha(reliability_data=merged[['llama','crowd']].to_numpy().T, level_of_measurement='ordinal')
```

## Evaluation signals

- Computed Krippendorff's Alpha values reproduce the Table IX pattern 0.99 (Llama-vs-Llama), 0.80 (GPT-vs-Llama), 0.27 and 0.19 (LLM-vs-crowd) within rounding tolerance
- Llama-vs-Llama intra-annotator alpha is near-perfect (0.99), confirming almost perfect intra-LLM agreement across repeated API calls
- LLM-vs-crowd alphas are low (≤ ~0.3) while inter-LLM alpha is high (~0.80), confirming the qualitative finding that LLM labels are self-consistent but diverge from crowdsourced labels
- All four label pairs contain the same matched instance set after joining LLM labels to crowdsourced labels via original dataset IDs, with no dropped or duplicated IDs
- Output CSV contains exactly eight metric values: one alpha and one MAE per pair

## Limitations

- The LLMPathy repository does not redistribute the full NewsEmp datasets due to license restrictions; only LLM-generated labels aligned with dataset IDs are provided, so the crowdsourced labels must be obtained separately from the CodeLab competition deposits
- Reproduction depends on matching LLM-generated labels back to source instances via the original message/article/speaker IDs; ID mismatches will silently degrade agreement scores
- The README notes corrections to previously published peak RMSE values (Tables V and VIII), so published numbers should be checked against the README's corrected tables when cross-referencing paper results
