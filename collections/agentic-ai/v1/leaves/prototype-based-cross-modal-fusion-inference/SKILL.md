# Prototype-based cross-modal fusion inference

## Summary

A fusion-inference procedure from EVL-MCoT that turns Long-CLIP visual tokens into a visual representation via learnable prototype-guided token fusion and attention-based fusion, then refines hateful/benign text features with a context-guided attention layer before computing an alignment score for harmful meme classification (ACC/AUROC).

## When to use

Use when classifying harmful memes (or similar vision-language tasks) from image-text pairs where fine-grained visual-textual alignment is needed and single-chain CoT reasoning is insufficient; inputs are Long-CLIP visual/textual embeddings plus multi-CoT chains.

## When NOT to use

- When CoT text sequences are short: the standard CLIP model struggles with inputs exceeding 20 tokens, so frozen vanilla CLIP encoders cannot replace Long-CLIP here
- When single-chain CoT reasoning from one MLLM is adequate — the article targets unreliable single-chain reasoning, so simpler direct-classification pipelines may suffice
- When no paired hateful/benign CoT texts can be generated, since both the prototype-guided and context-guided decoders depend on the two text streams

## Inputs

- Meme image-text pairs M = {I, T} (Hateful Memes test seen/unseen splits; MultiOFF memes)
- Multi-CoT chains (n=3 hateful, m=3 benign) generated by LLaVA-1.5-7B or GPT-4
- Long-CLIP visual token embeddings (248-token context) from the frozen visual encoder
- Long-CLIP text embeddings T_emb of the hateful/benign CoT texts from the frozen text encoder
- Ground-truth hateful/non-hateful labels

## Outputs

- Visual representation S from prototype-guided token fusion
- Enhanced text features T_embE from the context-guided attention layer
- Alignment scores with learnable temperature tau
- Benchmark metrics: ACC and AUROC on Hateful Memes Test Seen (75.88 / 79.25) and Test Unseen (75.57 / 79.40); ACC and F1 on MultiOFF (70.0 / 63.8)

## How to apply

Encode visual inputs with the frozen Long-CLIP visual encoder (248-token context, sufficient for ~150-word CoT sequences) and encode the paired hateful and benign CoT texts with the frozen Long-CLIP text encoder. Apply the prototype-guided token fusion mechanism: learnable prototype features act as queries over the visual tokens, then an attention-based feature fusion with learnable weights (W_a, W_b, W_v, W_c) aggregates the tokens into a final visual representation S. Next, apply the context-guided attention layer where the visual prototype features serve as queries Q and the text embeddings T_emb serve as both keys K and values V, yielding enhanced text features T_embE. Compute the alignment score with cross-entropy loss by avg-pooling the hateful/benign text features and concatenating them against S, using a learnable temperature parameter tau; train with AdamW (lr 5e-5, weight decay 0.01, cosine scheduler). Under the n=3, m=3 multi-CoT setting with LLaVA-1.5-7B (Hateful Memes) or GPT-4 (MultiOFF), run inference to report ACC and AUROC (Hateful Memes Test Seen/Unseen) or ACC and F1 (MultiOFF).

## Related tools

- **Long-CLIP** (Frozen visual and text encoder providing 248-token context for visual tokens and 150-word CoT sequences)
- **LLaVA-1.5-7B** (MLLM backbone generating the n=3, m=3 multi-CoT chains for Hateful Memes)
- **GPT-4** (MLLM backbone generating the multi-CoT chains for MultiOFF)
- **AdamW** (Optimizer for training the prototype-guided and context-guided decoders (lr 5e-5, weight decay 0.01, cosine scheduler))

## Evaluation signals

- Match reported metrics: ACC 75.88 and AUROC 79.25 on Hateful Memes Test Seen; ACC 75.57 and AUROC 79.40 on Test Unseen
- Match MultiOFF results: ACC 70.0 and F1 63.8, the best reported performance on that dataset
- Ablation check: removing Long-CLIP should significantly reduce ACC and AUROC, so fusion built on standard CLIP should underperform
- All baseline rows (Image-Grid, MMBT-Region, ViLBERT, VisualBERTCOCO, LLaVA-1.5-7B, GPT-4o, MOMENTA, SFT variants, RGCL) should be reproduced alongside the EVL-MCoT row in benchmark_results.csv
- Verify the learnable prototype features serve as queries in token fusion and the visual prototypes serve as queries with text embeddings as keys/values in the context-guided layer

## Limitations

- Reasoning chains are long (150-word CoT), which the article's future work aims to shorten while maintaining performance
- Repository components beyond train/ (model architectures, configs, scripts, pretrained weights) were 'coming soon' at the time, limiting turnkey reproduction
- MultiOFF is very small (743 memes), and it required a different MLLM backbone (GPT-4) than Hateful Memes (LLaVA-1.5-7B)
