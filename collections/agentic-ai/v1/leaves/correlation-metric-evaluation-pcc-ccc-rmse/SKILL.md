# correlation-metric-evaluation-pcc-ccc-rmse

## Summary

Evaluate empathy regression models on the NewsEmp benchmarks by computing Pearson correlation coefficient (PCC), concordance correlation coefficient (CCC), and RMSE over three random runs, reporting both median and peak scores so results are comparable to Table V/Table VIII of the LLMPathy paper.

## When to use

Use when comparing empathy-prediction regressors (e.g., RoBERTa or DeBERTa fine-tunes on NewsEmp22/23/24) against baselines like Giorgi et al., where PCC/CCC/RMSE reporting protocol must match the paper.

## When NOT to use

- Evaluation task is classification or rank-based rather than continuous empathy score regression, where PCC/CCC/RMSE are not the appropriate metrics
- Only a single run is available and median/peak-across-runs protocol cannot be followed, making scores incomparable with the paper's three-run reporting
- Data is not from the NewsEmp22/23/24 empathy benchmarks with continuous crowd-sourced or LLM-corrected labels

## Inputs

- Test-set predictions from src/test.py using a trained checkpoint (.ckpt) under logs/
- Ground-truth empathy scores from the NewsEmp24 test set (dataset from CodaLab competition 18810)
- Three runs (random seeds) of the same configuration for median/peak aggregation

## Outputs

- Peak PCC, CCC, and RMSE values (e.g., PCC 0.648, CCC 0.597, RMSE 0.021) and median scores across three runs
- Comparison table rows against the Giorgi et al. baseline (PCC 0.629/0.607)

## How to apply

After running `python src/test.py` on a trained checkpoint (e.g., a *.ckpt under logs/ such as the lr_3e-05_bs_16/alpha_4.0 configuration), compute PCC, CCC, and RMSE on the test-set predictions. Repeat across three random runs and report two kinds of scores: median scores (stability) and peak scores (maximum PCC/CCC, minimum RMSE). The peak protocol matters because the paper's corrected Table VIII shows the noise-mitigated RoBERTa model (NewsEmp24+23+22 combined data, Llama labels, alpha=4.0) reaches peak PCC 0.648 and CCC 0.597, exceeding Giorgi et al.'s baseline PCC of 0.607. Corrected RMSE reporting replaced erroneous values in the published Tables V and VIII, so always verify against the README's corrected tables rather than the IEEE Xplore/arXiv versions.

## Evaluation signals

- Peak PCC must reach 0.648 and peak CCC 0.597 for the noise-mitigated RoBERTa model (combined NewsEmp24+23+22, Llama labels, alpha=4.0), matching corrected Table VIII
- Reported peak metrics must exceed the Giorgi et al. baseline PCC of 0.607 (re-implemented comparison)
- RMSE peak is defined as the minimum RMSE across three runs; verify against corrected Table V values, not the published IEEE/arXiv tables
- Metrics must be computed over exactly three runs, with both median and peak scores reported for PCCs, CCCs and RMSEs
- y'(202x) logging convention in run names (e.g., logs/..._y'(2024,2022)-ImprovedEarlyStop-MultiAlpha/lr_3e-05_bs_16/alpha_4.0) must correspond to the label-correction configuration being scored

## Limitations

- RMSE peak-score reporting contained errors in the published Tables V and VIII; the corrected values appear only in the repository README, so published arXiv/IEEE versions overstate the correction to Giorgi et al.
- Datasets cannot be redistributed; NewsEmp22/23/24 must be obtained separately from CodaLab and matched to LLM-generated labels by instance IDs
- Peak-score selection (max PCC, min RMSE) over three runs may overstate expected performance relative to median scores
