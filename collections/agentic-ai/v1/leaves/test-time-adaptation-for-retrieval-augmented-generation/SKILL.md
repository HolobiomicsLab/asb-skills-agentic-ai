# test-time-adaptation-for-retrieval-augmented-generation

## Summary

TTARAG dynamically updates a language model's parameters at inference time using self-supervised learning signals generated by splitting retrieved passages into prefix-suffix pairs and training the model to predict the suffix from the prefix, improving RAG performance in specialized domains without new labeled data or retraining.

## When to use

Use when a RAG system faces distribution shifts or domain-specific dependencies in specialized domains and you need to adapt the LLM during inference without labeled data or model retraining.

## When NOT to use

- The task requires exact-match string scoring rather than semantic-equivalence judgment, since TTARAG's evaluation protocol relies on LLM-as-a-judge semantic equivalence (98% agreement with human annotators on 100 sampled examples).
- Retrieved passages fall below the configured minimum length threshold, leaving insufficient context for meaningful prefix-suffix adaptation.
- You need to answer whether segmentation into prefix-suffix pairs matters — in that case run the ablation that performs next-token prediction on the entire passage without prefix-suffix splitting instead of the full method.

## Inputs

- Retrieved passages per query (e.g. top 5 BM25 passages from Pyserini, or top 20 sentences reranked by MiniLM-v6 from Brave Search API HTML pages)
- Question-answer benchmark data (e.g. CRAG with 2,706 question-answer pairs, PubMedQA pqa_labeled with 1,000 pairs, BioASQ with 500 pairs)
- Base language model weights (e.g. Llama-3.1-8B-Instruct placed under models/)

## Outputs

- Adapted model parameters used to generate the final response per query
- Model predictions saved under predictions/ and summaries under results/<dataset>/
- Accuracy tables comparing TTARAG against baselines/ablations (e.g. results_table.tsv of CRAG overall accuracy for TTARAG vs the no-segmentation ablation)

## How to apply

Retrieve top passages (BM25 top 5 via Pyserini, or Brave Search API pages reranked by MiniLM-v6 to select top 20 sentences), then split each passage into prefix-suffix pairs using the two-tier passage-splitting strategy, filtering out passages shorter than the configured minimum length threshold. Run test-time adaptation with learning rates between 1e-6 and 1e-5 (e.g. 1e-5) and 3-5 adaptation pairs (e.g. --max_adapt_pairs 3), computing the loss on the suffix prediction task with prefix tokens masked during label preparation; accumulate gradients over two steps, clip to a maximum norm threshold, and update parameters with AdamW. Reset the model parameters to their original pre-trained state before each adaptation iteration to ensure a clean starting point. After adaptation, generate the final response with the adapted parameters and evaluate semantic equivalence against reference answers using an LLM-as-a-judge (Qwen2.5-72B-Instruct) rather than exact match.

## Examples

```
python parallel_evaluation.py --do_generate --dataset pubmedqa --model_name models/Llama-3.1-8B-Instruct --do_tta --learning_rate 1e-5 --max_adapt_pairs 3 --cross_encoder_name models/ms-marco-MiniLM-L-6-v2
```

## Evaluation signals

- Adaptation settings match the paper's optimum: learning rate in the 1e-6 to 1e-5 range and 3-5 adaptation pairs (e.g. --learning_rate 1e-5 --max_adapt_pairs 3).
- Loss is computed on the suffix prediction task with prefix tokens masked during label preparation, not on whole-passage next-token prediction.
- Model parameters are reset to the original pre-trained state before each adaptation iteration.
- Evaluation uses Qwen2.5-72B-Instruct LLM-as-a-judge semantic equivalence, not exact match; the judge should show ~98% agreement with human annotators on a 100-example sample.
- On CRAG overall with Llama-3.1-8B-Instruct, TTARAG reaches ~31.9 accuracy versus ~30.8 for the no-segmentation ablation, with consistent positive segmentation deltas across Llama-3.1-8B-Instruct (31.9 vs 30.8), Llama-2-7b-chat (30.5 vs 30.1), and ChatGLM-3-6b (25.7 vs 25.0).

## Limitations

- Performance is not sensitive to the number of adaptation pairs and learning rate, but optimal settings are 1e-6 to 1e-5 learning rate and 3-5 adaptation pairs.
- Passages shorter than the configured minimum length threshold must be filtered out, limiting adaptation signal on short retrievals.
- Per-query adaptation adds processing time: 1.75s (1-pair) to 2.60s (5-pair), though still lower than CoT's 4.32s.
- The six specialized domains and quantitative improvement metrics over naive-RAG are not reported in all paper sections; no changelog exists in the TTARAG repository.
