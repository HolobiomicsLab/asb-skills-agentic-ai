# hateful-meme-classification-model-training

## Summary

Training pipeline for EVL-MCoT, a vision-language multi-CoT model for harmful meme detection on Hateful Memes and MultiOFF, combining Long-CLIP encoding, prototype-guided and context-guided decoders, and multi-CoT reasoning (n=3, m=3) generated by LLaVA-1.5-7B or GPT-4.

## When to use

Use when training or reproducing a multimodal harmful-meme classifier whose inputs are meme image-text pairs, especially when CoT reasoning chains and cross-modal fusion decoders must be configured and tuned.

## When NOT to use

- Input memes have text descriptions exceeding ~20 tokens and Long-CLIP has been replaced by standard CLIP, which 'struggles with inputs exceeding 20 tokens' and cannot process the 150-word CoT sequences
- The goal is single-chain CoT ablation or component-removal analysis rather than training the full model (see the ablation skill)
- The task is not harmful-meme classification but another multimodal task, since the training pipeline is built around Hateful Memes and MultiOFF label schemes

## Inputs

- Hateful Memes dataset (>10,000 multimodal meme examples labeled hateful/non-hateful)
- MultiOFF dataset (743 memes labeled offensive/non-offensive)
- Multi-CoT reasoning chains (n=3, m=3) generated via LLaVA-1.5-7B or GPT-4
- Meme images and text encoded by frozen Long-CLIP (248-token context)

## Outputs

- Trained EVL-MCoT model weights from the train/ pipeline
- Accuracy and AUROC metrics on Hateful Memes Test Seen and Test Unseen
- Accuracy and F1 metrics on MultiOFF
- Training logs from the training loop

## How to apply

Clone github.com/BGWH123/EVL-MCoT and use the training code in the train/ directory. Configure the model with the full multi-CoT setting (n=3, m=3), using LLaVA-1.5-7B as the MLLM for Hateful Memes and GPT-4 for MultiOFF; Long-CLIP (248-token context) encodes both visuals and hateful/benign text through the frozen encoders, feeding the prototype-guided token fusion decoder and the context-guided attention layer (visual prototypes as queries, text features as keys and values). Train with AdamW (learning rate 5e-5, weight decay 0.01, cosine learning rate scheduler), batch size 8 with gradient accumulation every 2 steps, on NVIDIA RTX 3090/4090 GPUs. Evaluate on Hateful Memes Test Seen/Test Unseen (ACC, AUROC) and MultiOFF (ACC, F1). The full model should reach 75.88 ACC / 79.25 AUROC on Test Seen and 70.0 ACC / 63.8 F1 on MultiOFF.

## Related tools

- **Long-CLIP** (Frozen visual and text encoder extending context length to 248 tokens for encoding meme images and hateful/benign text features)
- **LLaVA-1.5-7B** (MLLM used to generate multi-CoT reasoning chains for the Hateful Memes experiments (n=3, m=3))
- **GPT-4** (MLLM used to generate multi-CoT reasoning chains for the MultiOFF experiments (n=3, m=3))
- **AdamW** (Optimizer with learning rate 5e-5, weight decay 0.01, and cosine learning rate scheduler)

## Examples

```
git clone https://github.com/BGWH123/EVL-MCoT && cd EVL-MCoT && python train/train.py --n 3 --m 3 --mlm llava-1.5-7b --lr 5e-5
```

## Evaluation signals

- Full model (n=3, m=3) with LLaVA reproduces 75.88 accuracy and 79.25 AUROC on Hateful Memes Test Seen
- Full model with GPT-4 reproduces 70.0 accuracy and 63.8 F1 on MultiOFF
- Training uses AdamW with learning rate 5e-5, weight decay 0.01, cosine scheduler, batch size 8, gradient accumulation every 2 steps
- Encoders are frozen Long-CLIP (248-token context), and visual prototypes serve as queries against text key-value pairs in the context-guided attention layer
- Trained pipeline resides in the repo's train/ directory with logging and evaluation scripts

## Limitations

- Repository currently ships only the train/ directory; model definitions (models/), configs, scripts, requirements.txt, pretrained weights, and usage instructions are marked 'coming soon' in the README
- Long-CLIP is required because standard CLIP cannot handle inputs exceeding 20 tokens, while the CoT approach requires processing 150-word sequences
- Future work notes strategies for shortening the reasoning chains while maintaining performance, implying the full (n=3, m=3) setting is costly
