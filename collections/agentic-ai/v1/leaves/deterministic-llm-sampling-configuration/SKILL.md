# deterministic-llm-sampling-configuration

## Summary

Configures LLM inference with near-deterministic sampling settings (temperature 0, top_p 0.01) so each essay yields exactly six comma-separated numeric Batson subscale scores, enabling reproducible scale-aware empathy labelling for the NewsEmp22/23/24 benchmarks.

## When to use

Use when generating per-instance numeric labels with an LLM where reproducibility and strict output format (exactly six comma-separated scores) are required, e.g. reconstructing LLM-generated empathy labels.

## When NOT to use

- The input labels are already crowdsourced gold annotations — this skill is for generating LLM labels, not for training the baseline y(202x) configuration
- The downstream task requires free-form or generative LLM output rather than strictly six numeric subscale scores in a fixed range
- The dataset lacks the instance identifiers needed to align generated labels back to the source data (the public datasets restrict redistribution, so alignment via IDs is mandatory)

## Inputs

- Essay texts and instance identifiers (message IDs, article IDs, speaker IDs) from NewsEmp22, NewsEmp23 and NewsEmp24 datasets obtained from their Codalab competition pages
- Batson six-subscale prompt template (Table I of the paper)
- config/config_common.yaml specifying the LLM-generated label column name (e.g. y_llm)

## Outputs

- Labels file in data/llm-generated-labels directory containing, per instance, the instance identifier, six Batson subscale scores (1.0–7.0) and the averaged empathy score y*
- Records whose column naming matches the y_llm configuration used for the second application scenario (LLM-generated labels)

## How to apply

Build the scale-aware prompt for each essay by pairing the essay text with the Batson six-subscale template (sympathetic, moved, compassionate, tender, warm, softhearted), asking for scores between 1.0 and 7.0 per emotion. Query the LLM with deterministic sampling settings — temperature 0 and top_p 0.01 — so each essay yields exactly six comma-separated numeric subscale scores. Parse the response, verify that six numeric values were returned and that each falls within the 1.0–7.0 valid range, then average them into a single empathy score y* per instance. Align each y* with its instance identifier (message IDs, article IDs, speaker IDs) and write records to the data/llm-generated-labels directory using column names consistent with the LLM-generated label column specified in config/config_common.yaml. This deterministic configuration is what makes the LLM-generated labels reproducible enough to serve as training supervision for RoBERTa/DeBERTa PLMs.

## Related tools

- **Python** (Scripting language for building the scale-aware prompts, querying the LLM, parsing/validating the six numeric scores, and writing the labels file) — https://github.com/hasan-rakibul/LLMPathy
- **pip** (Installs the repository dependencies required to run the labelling and training pipeline) — https://github.com/hasan-rakibul/LLMPathy

## Examples

```
python src/label.py --temperature 0 --top_p 0.01 --prompt-template batson_six_subscale --scores-range 1.0-7.0 --out data/llm-generated-labels/newsemp22_llm_labels.csv
```

## Evaluation signals

- Output file exists in data/llm-generated-labels and every record contains an instance identifier plus six subscale scores and the averaged y*
- All six parsed subscale scores fall within the valid 1.0–7.0 numeric range
- Exactly six comma-separated numeric values are returned per essay when the LLM is queried
- Column naming in the labels file matches the y_llm LLM-generated label column specified in config/config_common.yaml
- Re-running the pipeline with temperature 0 and top_p 0.01 reproduces the same y* per instance identifier

## Limitations

- The public NewsEmp22/23/24 datasets restrict redistribution, so only the LLM-generated labels (aligned with original dataset IDs) are shipped; users must obtain the essays from the Codalab competition pages to reproduce end-to-end
- Label quality depends on the psychology-based prompt design; the paper reports peak RMSE corrections in Tables V and VIII, so published metric values may differ from the corrected README tables
