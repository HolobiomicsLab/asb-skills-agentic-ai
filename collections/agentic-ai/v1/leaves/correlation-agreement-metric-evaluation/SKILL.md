# correlation-agreement-metric-evaluation

## Summary

Evaluates empathy regression models (RoBERTa/DeBERTa PLMs on NewsEmp data) using Pearson Correlation Coefficient (PCC), Concordance Correlation Coefficient (CCC), and RMSE, aggregated as median and peak scores across three runs per configuration to compare LLM-label-augmented training against crowdsourced-label baselines.

## When to use

Use when comparing regression models trained on continuous empathy scores where both correlation (PCC, CCC) and error (RMSE) must be reported as median and peak statistics over multiple runs, e.g., label-noise or data-augmentation experiments.

## When NOT to use

- When the task is classification (e.g., emotion category prediction) rather than regression on continuous empathy scores — PCC/CCC/RMSE median-and-peak aggregation is designed for regression metrics
- When only a single run per configuration is available — median and peak statistics over three runs cannot be computed reliably
- When the goal is comparing against external baselines on a single metric only, where the full median/peak aggregation protocol is unnecessary

## Inputs

- Saved model checkpoints (.ckpt files) under logs/<timestamp>_<scenario>/ directories
- config/config_test.yaml with test_from_ckpts_parent_dir or test_from_checkpoint path set
- NewsEmp22/NewsEmp24 test sets with crowdsourced ground-truth empathy scores
- Trained models from augmentation scenarios (e.g., y(202x)+y_llm(202y)) and baselines (y(202x))

## Outputs

- Per-run PCC, CCC, and RMSE values from python src/test.py
- Aggregated median and peak PCC, CCC, RMSE per configuration (peak RMSE = minimum over runs)
- table_vi_metrics.csv comparing D_train+ vs crowdsourced-label baseline across data and PLM setups

## How to apply

After training, evaluate saved checkpoints by setting `test_from_ckpts_parent_dir` (e.g., `logs/20241115_005338_y'(2024,2022)-ImprovedEarlyStop-MultiAlpha/lr_3e-05_bs_16/alpha_4.0`) or `test_from_checkpoint` in `config/config_test.yaml` and running `python src/test.py`. Run each configuration three times, then aggregate PCC, CCC, and RMSE across runs computing both median and peak scores, where peak RMSE is defined as the minimum RMSE over runs. Report median and peak for all three metrics across the four data and PLM setups (RoBERTa/DeBERTa on NewsEmp22/NewsEmp24 augmentation scenarios, e.g., y(2024)+y_llm(2022)). Acceptance requires the LLM-labelled augmentation (D_train+) to outperform the crowdsourced-only baseline on median and peak PCC, CCC, and RMSE. Write the metric comparison to table_vi_metrics.csv. Beware a known error mode: peak RMSE must be the minimum (best), not maximum, RMSE across runs — misreporting this affected Tables V and VIII of the published paper and required a README correction.

```
python src/test.py  # with test_from_ckpts_parent_dir=logs/20241115_005338_y'(2024,2022)-ImprovedEarlyStop-MultiAlpha/lr_3e-05_bs_16/alpha_4.0 in config/config_test.yaml
```

## Evaluation signals

- Metrics written to table_vi_metrics.csv contain all three metrics (PCC, CCC, RMSE) as median and peak for each of three runs per configuration
- Peak RMSE equals the minimum (not maximum) RMSE across the three runs — the exact error corrected in the README's updated Tables V and VIII
- LLM-labelled augmentation (e.g., NewsEmp24 + Llama-labelled NewsEmp22: median PCC 0.513, CCC 0.490, RMSE 1.484) matches or exceeds the crowdsourced-only baseline on all three metrics
- Checkpoints are loaded via test_from_ckpts_parent_dir or test_from_checkpoint and evaluated with python src/test.py without training-time metrics leaking into the comparison

## Limitations

- Peak RMSE reporting is error-prone: minor errors selecting the minimum RMSE from three runs affected Tables V and VIII of the published paper and required post-publication correction
- Datasets cannot be redistributed; labels are aligned to original instances via message/article/speaker IDs, so evaluation depends on obtaining NewsEmp22/23/24 from Codalab
- Results depend on the specific PLM/torch pairing (RoBERTa: torch 2.4.1 + ROCm 6.1; DeBERTa: torch 2.2.0 + ROCm 5.7.3); mixing configurations may not reproduce published numbers
