# meme-image-text-alignment-classification

## Summary

Implements EVL-MCoT's prototype-guided and context-guided decoder fusion for harmful meme detection, aligning Long-CLIP visual tokens with hateful/benign CoT text embeddings via learnable prototypes and a temperature-scaled alignment score for classification.

## When to use

Use when classifying memes as hateful/non-hateful (or offensive/non-offensive) and you need fine-grained visual-textual fusion beyond shallow cross-modal alignment, with multi-CoT text available.

## When NOT to use

- The meme's caption/image text is short enough that the standard CLIP encoder suffices and no CoT reasoning is needed
- You lack multi-CoT text inputs (hateful and benign reasoning chains); the decoder is designed to align those CoT embeddings with visual prototypes, not raw captions alone

## Inputs

- Visual tokens H in R^{N x M x D} from the frozen Long-CLIP visual encoder per meme image
- Text embeddings T_emb from the frozen Long-CLIP text encoder for hateful and benign CoT texts per meme
- Hateful Memes dataset examples (over 10,000 multimodal examples) or MultiOFF memes (743 memes)
- Multi-CoT texts generated by an MLLM (LLaVA-1.5-7B or GPT-4) with n=3, m=3 setting

## Outputs

- Refined visual features S from the prototype-guided decoder
- Enriched hateful and benign text representations Th_embE and Tb_embE
- Binary classification logits (hateful vs non-hateful / offensive vs non-offensive)
- Accuracy and AUROC metrics (e.g., 75.88% / 79.25 on Hateful Memes Test Seen)

## How to apply

Load visual tokens H (N x M x D) and text embeddings T_emb from the frozen Long-CLIP encoders for each meme's hateful and benign CoT texts. Run a prototype-guided decoder: P learnable prototypes attend over visual tokens via cross-attention (Softmax(Pr H^T / sqrt(D))H) with layer norm and residual connection (Eq. 2), then derive refined visual features S using tanh-softmax attention-based feature fusion with trainable matrices W_a, W_b, W_c, W_v (Eqs. 3-5). Apply a context-guided attention layer using prototype features Pr~ as queries and text features T_emb as keys/values (Eq. 6) to enrich the hateful and benign text representations. Compute classification logits by concatenating average-pooled hateful/benign text features, taking the scaled dot product with S, and multiplying by a learnable temperature tau (Eq. 7), trained with cross-entropy. Train with AdamW (lr 5e-5, weight decay 0.01, cosine scheduler, batch size 8 with gradient accumulation every 2 steps).

## Related tools

- **Long-CLIP** (Frozen visual and text encoders producing visual tokens H and CoT text embeddings T_emb; extends context length to 248 tokens for 150-word CoT sequences)
- **LLaVA-1.5-7B** (MLLM used to generate the multi-CoT reasoning chains consumed by the decoder (setting n=3, m=3))
- **GPT-4** (Alternative MLLM for generating the multi-CoT reasoning chains (setting n=3, m=3))
- **AdamW** (Optimizer with learning rate 5e-5, weight decay 0.01, and cosine learning rate scheduler for training the fusion module)

## Examples

```
python train/train.py --visual_encoder long-clip --text_encoder long-clip --cot_texts hateful_benign. --lr 5e-5 --batch_size 8 --grad_accum 2
```

## Evaluation signals

- Accuracy near the reported 75.88% and AUROC near 79.25 on Hateful Memes Test Seen (75.57%/79.40 on Test Unseen)
- On MultiOFF, accuracy near 70.0 and F1 near 63.8
- Removing Long-CLIP from the pipeline should significantly reduce ACC and AUROC; if it does not, the fusion is not using fine-grained visual tokens
- Context-guided layer output should be textual features whose keys/values come from T_emb with prototype queries Pr~, per Eq. 6
- Training loss should decrease under AdamW (lr 5e-5, batch size 8, gradient accumulation every 2 steps) with cross-entropy on Eq. 7 logits

## Limitations

- Long-CLIP must remain frozen for token extraction; the standard CLIP model struggles with inputs exceeding 20 tokens, while the CoT approach requires processing 150-word sequences
- Future work targets shortening the reasoning chains while maintaining performance — long chains are costly
- Repository README indicates models/, configs/, and scripts/ are not yet released; only the train/ pipeline is currently available
