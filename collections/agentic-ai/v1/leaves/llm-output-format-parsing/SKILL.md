# llm-output-format-parsing

## Summary

Parses deterministic LLM responses into structured numeric labels by validating that each prompt response yields exactly the expected comma-separated values, then averaging them into a single score per instance. In the LLMPathy empathy pipeline this converts six Batson emotional-appraisal subscale scores (1.0–7.0) into one LLM-generated empathy label y*.

## When to use

Use when an LLM is queried with a fixed-item rating prompt (e.g., Batson's six subscales) and raw free-text responses must be converted into validated, per-instance numeric records for downstream model training.

## When NOT to use

- When labels are already structured crowdsourced scores (the baseline y(202x) scenario) — no LLM output parsing is needed
- When the downstream experiment uses noisy label correction (the y'(202x) alpha-modification scenario) rather than LLM-generated labels
- When the LLM prompt output schema is free-form or not constrained to a fixed number of numeric items — validation rules here assume exactly six scores in 1.0–7.0

## Inputs

- Raw LLM responses (six comma-separated numeric values per essay) generated with scale-aware prompts over NewsEmp22/NewsEmp23/NewsEmp24 essay texts
- Instance identifiers (message IDs, article IDs, speaker IDs) matching the source datasets from the Codalab competition pages
- config/config_common.yaml specifying the LLM-generated and crowdsourced label column names

## Outputs

- Labels file in data/llm-generated-labels containing per-instance records: instance identifier, six subscale scores, and averaged empathy score y*
- Validated y_llm label column (e.g., y_llm(202x)) usable for the training-data-augmentation application scenario

## How to apply

Query the LLM with deterministic sampling settings (temperature 0, top_p 0.01) so each essay response is stable and parseable. Parse each response expecting exactly six comma-separated numeric subscale scores corresponding to Batson's emotions (sympathetic, moved, compassionate, tender, warm, softhearted), each in the 1.0–7.0 range; re-query or flag any response failing the count or range check. Average the six validated subscale scores into a single empathy score y* per instance, and align each y* with its dataset instance identifier (message ID, article ID, speaker ID). Write records to a labels file in the data/llm-generated-labels directory, using column names consistent with the LLM-generated label column configured in config/config_common.yaml (e.g., the y_llm label naming such as y_llm(202x)).

## Examples

```
scores = [float(s) for s in llm_response.strip().split(',')]; assert len(scores) == 6 and all(1.0 <= s <= 7.0 for s in scores); y_star = sum(scores) / 6
```

## Evaluation signals

- Every parsed record contains exactly six numeric subscale scores plus the instance identifier and the averaged y*
- All subscale scores fall within the valid 1.0–7.0 range for Batson's emotional-appraisal subscales
- Output file exists in data/llm-generated-labels and its label-column naming matches the y_llm configuration in config/config_common.yaml
- Each y* aligns correctly with its dataset instance identifier (message ID, article ID, or speaker ID) from the NewsEmp22/23/24 source data
- Determinism check: re-running with temperature 0, top_p 0.01 yields the same six scores per essay

## Limitations

- The source datasets restrict redistribution, so labels can only be matched back to essays via instance identifiers; full essays are not shipped in the repository
- Parsing assumes the prompt constrains the LLM to exactly six comma-separated numeric values; non-conforming responses must be re-queried or rejected
- The repository was built and tested only on torch 2.2.0/Python 3.10.12 and torch 2.4.1/Python 3.12.3; other environments are untested
