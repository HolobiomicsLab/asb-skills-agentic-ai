# noisy-label-correction-alpha-sweep

## Summary

Mitigates noisy crowdsourced empathy labels (e.g., NewsEmp24) by correcting them with LLM-generated labels selected via a scale-aware threshold alpha, then fine-tuning a PLM (RoBERTa/DeBERTa) on the corrected labels and evaluating PCC/CCC/RMSE on a hold-out test split.

## When to use

Use when supervised empathy regression on crowdsourced emotion/empathy scores underperforms due to label noise, and LLM-generated labels are available to correct training targets via an alpha sweep before PLM fine-tuning.

## When NOT to use

- The goal is the second application scenario (training data augmentation, y_llm), where LLM labels are added rather than used to correct existing crowdsourced labels
- The task requires reproducing the published Tables V/VIII peak RMSE values verbatim — the README reports errors in the published peak RMSE scores and provides corrected tables
- The input dataset is not one of the NewsEmp22/23/24 benchmarks with available LLM-generated labels for the same instance IDs

## Inputs

- NewsEmp24 training split with crowdsourced (CS) empathy labels
- LLM-generated labels (e.g., Llama or GPT) aligned to dataset instance IDs from data/llm-generated-labels
- Pre-trained language model checkpoint (RoBERTa or DeBERTa)
- config/config_common.yaml (model name, CS vs LLM label column names)

## Outputs

- Fine-tuned PLM checkpoints under logs/<timestamp>_y'(2024)-ImprovedEarlyStop-MultiAlpha/lr_3e-05_bs_16/alpha_<x>/
- Test-split metrics (PCC, CCC, RMSE) per alpha and per run
- Aggregated median and peak metric table (corrected Table V-style comparison, e.g., table_v_metrics.csv)

## How to apply

Build LLM-corrected labels y'(2024) by modifying the crowdsourced NewsEmp24 labels based on the alpha parameter (e.g., alpha=4.0 to 4.5, best at alpha=4.5 with Llama labels), distinguishing CS vs LLM label columns in config/config_common.yaml. Fine-tune RoBERTa (torch 2.4.1 + ROCm 6.1) or DeBERTa (torch 2.2.0 + ROCm 5.7.3) with the ImprovedEarlyStop-MultiAlpha setup using learning rate 3e-05 and batch size 16, submitting runs via the job_test.sh SLURM script on Pawsey Setonix. Evaluate on the hold-out NewsEmp24 test split by setting test_from_ckpts_parent_dir or test_from_checkpoint in config/config_test.yaml and running python src/test.py. Aggregate median and peak PCC, CCC, and RMSE across the alpha sweep, five runs, and all four data+PLM setups, comparing against the crowdsourced-label baseline; acceptance is the corrected-label model outperforming the baseline, with reported peak PCC 0.648, CCC 0.597, RMSE 0.021.

```

```

## Evaluation signals

- Corrected-label model's median and peak PCC/CCC/RMSE outperform the crowdsourced-label baseline across all four data and PLM setups
- Peak metrics approach PCC 0.648, CCC 0.597, and RMSE 0.021 (best at alpha=4.5, Llama labels, NewsEmp24+23+22 with RoBERTa) across five runs
- Run directories follow the naming pattern y'(202x)-ImprovedEarlyStop-MultiAlpha/lr_3e-05_bs_16/alpha_<x> (e.g., alpha_4.0)
- Test metrics are computed on the hold-out NewsEmp24 test split via python src/test.py with the checkpoint path set in config/config_test.yaml

## Limitations

- Published peak RMSE scores in Tables V and VIII were misreported (minimum over three runs); corrected tables are provided in the README and values in brackets are updated
- Original NewsEmp datasets restrict redistribution; only LLM-generated labels aligned to dataset IDs are shipped, so users must obtain NewsEmp22/23/24 from CodaLab and match labels by message/article/speaker IDs
- Experiments are tied to specific software stacks (torch 2.4.1 + ROCm 6.1 for RoBERTa; torch 2.2.0 + ROCm 5.7.3 for DeBERTa) and Pawsey Setonix SLURM execution
