# llm-label-training-data-augmentation

## Summary

Augments PLM-based empathy prediction training data (NewsEmp22/NewsEmp24) with labels generated by LLMs (GPT/Llama) using psychology-based scale-aware prompts, so that D_train+ = crowdsourced labels + LLM-generated labels outperforms the crowdsourced-only baseline on PCC, CCC and RMSE.

## When to use

Use when extending an empathy-prediction training set (e.g. NewsEmp24 with NewsEmp22 instances) and crowdsourced labels for the added data are unavailable or noisy, so LLM-generated labels can supplement them.

## When NOT to use

- When the goal is correcting noisy crowdsourced labels in place (noisy label correction, the y'(202x) 1st application scenario / Table V) rather than augmenting training data with additional LLM-labelled instances (Table VI).
- When no original dataset instance IDs are available to align with the LLM-generated label files, since labels are distributed only as identifiers paired with generated scores.

## Inputs

- NewsEmp22 dataset (https://codalab.lisn.upsaclay.fr/competitions/834)
- NewsEmp24 dataset (https://codalab.lisn.upsaclay.fr/competitions/18810)
- LLM-generated label files in data/llm-generated-labels keyed by message/article/speaker IDs
- config/config_common.yaml with pre-trained model and crowdsourced vs LLM-generated label column names

## Outputs

- Trained PLM checkpoints under logs/ for the y(202x)+y_llm(202y) augmentation scenario
- Test-set PCC, CCC, and RMSE metrics aggregated (median and peak) across three runs per configuration
- Metric comparison written to table_vi_metrics.csv

## How to apply

Obtain the original NewsEmp22 (codalab competition 834) and NewsEmp24 (codalab competition 18810) datasets and align the LLM-generated labels in data/llm-generated-labels to original instances via message/article/speaker IDs, since the source datasets cannot be redistributed. Specify the pre-trained model (RoBERTa or DeBERTa) and the crowdsourced vs LLM-generated label column names in config/config_common.yaml, then launch training for the y(202x)+y_llm(202y) augmentation scenario (e.g. logs/20241230_095259_y(2022)-y_llm(2024)-gpt = NewsEmp24 combined with GPT-labelled NewsEmp22). Run RoBERTa experiments under torch 2.4.1 with ROCm 6.1 (installed via python -m pip install requirements_torch_rocm.txt for AMD GPUs) and DeBERTa experiments under torch 2.2.0 with ROCm 5.7.3, optionally submitting via the job_test.sh SLURM script on the Pawsey Setonix cluster. Evaluate saved checkpoints by setting test_from_ckpts_parent_dir or test_from_checkpoint in config/config_test.yaml and running python src/test.py. Aggregate PCC, CCC, and RMSE across three runs per configuration, computing both median and peak scores (peak RMSE = minimum RMSE over runs), and compare D_train+ against the crowdsourced-only baseline; the best configuration (NewsEmp24 + Llama-labelled NewsEmp22) achieves median PCC 0.513, CCC 0.490, RMSE 1.484.

## Evaluation signals

- Models trained on crowdsourced labels supplemented with LLM-generated labels outperform the crowdsourced-only baseline on median and peak PCC, CCC, and RMSE across all four data and PLM setups.
- Best configuration (NewsEmp24 training extended with Llama-labelled NewsEmp22) reaches median PCC 0.513, CCC 0.490, and RMSE 1.484.
- Each configuration is run three times and both median and peak (peak RMSE = minimum RMSE over runs) scores are reported.
- LLM-generated labels align cleanly to original instances via message/article/speaker IDs before training.
- Metric comparison is written to table_vi_metrics.csv consistent with the corrected Table VI results.

## Limitations

- The public NewsEmp datasets restrict redistribution, so only LLM-generated labels with instance identifiers are provided; users must obtain the source datasets separately from Codabench/CodaLab.
- Peak RMSE reporting errors were found in the published Tables V and VIII of the paper; corrected values are in the repository README.
- Different PLMs require different torch/ROCm stacks (RoBERTa: torch 2.4.1 + ROCm 6.1; DeBERTa: torch 2.2.0 + ROCm 5.7.3), so environments cannot be mixed across PLM setups.
