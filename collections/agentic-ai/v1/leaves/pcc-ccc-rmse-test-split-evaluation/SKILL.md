# pcc-ccc-rmse-test-split-evaluation

## Summary

Evaluates empathy-regression PLM checkpoints on a hold-out dataset test split (e.g., NewsEmp24) using three agreement metrics — Pearson correlation coefficient (PCC), concordance correlation coefficient (CCC), and RMSE — reporting median and peak scores across runs, as in the LLMPathy/NewsEmp Table V protocol.

## When to use

Use when a trained empathy-regression model (RoBERTa/DeBERTa checkpoint on NewsEmp-style data) needs held-out test evaluation with PCC/CCC/RMSE, aggregated as median and peak (best) scores over multiple runs.

## When NOT to use

- Evaluating on the validation/training data instead of the hold-out test split — results are not comparable to the paper's Table V numbers
- Reporting only a single metric such as PCC — the paper's protocol requires PCC, CCC, and RMSE together because PCC ignores scale/slope agreement
- Classification or categorical empathy tasks — the skill targets continuous empathy-score regression evaluated with agreement metrics

## Inputs

- Trained PLM checkpoint file (*.ckpt) from an ImprovedEarlyStop-MultiAlpha training run
- config/config_test.yaml with test_from_ckpts_parent_dir or test_from_checkpoint set
- Hold-out test split of NewsEmp24 (and optionally NewsEmp22/NewsEmp23) with gold empathy scores
- config/config_common.yaml specifying the PLM (RoBERTa or DeBERTa) and label column names (crowdsourced CS vs LLM-generated)

## Outputs

- Test-split PCC, CCC, and RMSE scores per checkpoint/run
- Median and peak (best) PCC/CCC/RMSE aggregated across runs and alpha sweep
- Corrected Table V-style comparison table (e.g., table_v_metrics.csv) across the four data-and-PLM setups

## How to apply

Configure the checkpoint path in config/config_test.yaml — either set test_from_ckpts_parent_dir to a run directory (e.g., logs/20241115_005338_y'(2024,2022)-ImprovedEarlyStop-MultiAlpha/lr_3e-05_bs_16/alpha_4.0) or test_from_checkpoint to a specific ckpt.ckpt — then run python src/test.py, which loads the checkpoint and evaluates on the hold-out test split. Evaluate on the NewsEmp24 test split (not validation) so results are comparable to the paper's Table V/II comparisons. Run each configuration across multiple runs (five runs in the paper; peak RMSE is the minimum over three runs) and report both the median and the peak (best) PCC, CCC, and RMSE. Note that CCC and RMSE are the stricter agreement metrics — PCC alone ignores scale bias, which matters when LLM-generated labels replace crowdsourced ones. Aggregate the corrected scores across all four data-and-PLM setups (NewsEmp24+23+22 with RoBERTa and DeBERTa) into a comparison table (e.g., table_v_metrics.csv) to compare noise-mitigated training against the crowdsourced-label baseline.

```

```

## Evaluation signals

- Noise-mitigated model's median and peak PCC exceeds the crowdsourced-label baseline across all four data-and-PLM setups (corrected Table V)
- Peak PCC reaches ~0.648, CCC ~0.597, and RMSE ~0.021 for the best setup (alpha=4.5, Llama labels, NewsEmp24+23+22, RoBERTa)
- Median and peak scores are both reported; peak RMSE is the minimum value selected from three runs
- Test is run on the hold-out NewsEmp24 test split via python src/test.py with a valid checkpoint path resolving to a saved ckpt.ckpt
- Comparison against Giorgi et al. benchmark (Table VIII) shows the approach outperforming on all three metrics

## Limitations

- Reported peak RMSE scores in Tables V and VIII of the published (IEEE/arXiv) version contained minor errors; corrected tables appear in the repository README — always use the corrected values
- Public NewsEmp datasets restrict redistribution, so evaluation requires obtaining the original datasets from CodaLab (competitions 834, 11167, 18810) and matching LLM-generated labels by instance IDs
- Results are aggregated over runs (peak RMSE from three runs; five runs reported in the finding) — a single run's metrics may not reproduce the paper's peak scores
