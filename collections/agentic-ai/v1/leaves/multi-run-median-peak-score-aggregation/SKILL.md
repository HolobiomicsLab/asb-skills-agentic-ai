# multi-run-median-peak-score-aggregation

## Summary

Aggregate empathy-prediction evaluation metrics (PCC, CCC, RMSE) across three training runs per configuration, reporting median and peak scores, so that LLM-label augmentation experiments on NewsEmp22/NewsEmp24 data are compared robustly against crowdsourced-label baselines.

## When to use

Use when a PLM empathy-prediction configuration (e.g. RoBERTa or DeBERTa on NewsEmp22/NewsEmp24) has been trained multiple times (3 runs) and checkpoint-level PCC, CCC and RMSE values must be summarised into median and peak scores for baseline-vs-augmentation comparison.

## When NOT to use

- Only a single training run exists per configuration, so a median/peak over three runs cannot be computed
- The goal is cross-dataset generalisation testing (e.g. Table VIII comparison against Giorgi et al.) rather than the Table VI augmentation-vs-baseline comparison
- Evaluating the noisy-label-correction scenario (y' alpha-modified labels, Table V) rather than the training-data-augmentation scenario (y+y_llm, Table VI)

## Inputs

- Saved model checkpoints from three training runs per configuration (e.g. logs/20241230_095259_y(2022)-y_llm(2024)-gpt style run directories)
- config/config_test.yaml with test_from_ckpts_parent_dir or test_from_checkpoint set
- Crowdsourced-label baseline run metrics for comparison (Table VI setting)

## Outputs

- table_vi_metrics.csv with median and peak PCC, CCC and RMSE per data/PLM setup
- Median and peak metric comparison of D_train+ (LLM-labelled augmentation) versus crowdsourced-label baseline across all four data and PLM setups

## How to apply

For each configuration, save checkpoints from three independent training runs, then evaluate each checkpoint by setting `test_from_ckpts_parent_dir` or `test_from_checkpoint` in `config/config_test.yaml` and running `python src/test.py`. From the three runs per configuration, compute the median PCC, CCC and RMSE, and compute peak scores as the maximum PCC and CCC and the minimum RMSE (peak RMSE = minimum RMSE over runs). Aggregate these for every data/PLM setup — e.g. RoBERTa under torch 2.4.1 with ROCm 6.1 and DeBERTa under torch 2.2.0 with ROCm 5.7.3 — across the y(202x)+y_llm(202y) augmentation scenario and the crowdsourced-label baseline. Compare D_train+ (crowdsourced labels supplemented with LLM-generated labels) against the crowdsourced-only baseline on both median and peak metrics across all four data and PLM setups, and write the metric comparison to `table_vi_metrics.csv`. Because peak RMSE values were misreported in the published Tables V and VIII, prefer the corrected README tables when cross-checking reported numbers.


## Evaluation signals

- Exactly three runs per configuration are aggregated before computing median and peak values
- Peak RMSE is defined as the minimum RMSE over the three runs (not the maximum), matching the README's corrected definition
- Peak PCC and peak CCC are the maximum values over the three runs
- The augmented configuration (crowdsourced + LLM-generated labels) outperforms the crowdsourced-only baseline on median and peak PCC, CCC and RMSE across all four data and PLM setups
- Comparison metrics are written to table_vi_metrics.csv

## Limitations

- Peak RMSE values were misreported in the published Tables V and VIII; the corrected values are only in the repository README
- The public NewsEmp22/NewsEmp23/NewsEmp24 datasets cannot be redistributed, so label aggregation and re-evaluation require obtaining the originals from the Codalab competitions and aligning LLM-generated labels via message/article/speaker IDs
- DeBERTa experiments require a different torch/ROCm stack (torch 2.2.0 with ROCm 5.7.3) than RoBERTa experiments (torch 2.4.1 with ROCm 6.1), so metrics from the two PLMs are not produced under identical environments
